# The 1985 transcripts are not reproducible — and never were

**Date:** 2026-08-27 · **Status:** finding, recorded for future comparison work

The two hand-made SSGGSM English transcripts in `_work/` cannot be regenerated by
anyone, including the person who made them. Their ASR runs recorded only part of
the configuration that produced them. This is a gap in the old evidence, not a
defect in the current code, and it changes how any future comparison against them
must be read.

---

## 1. What was measured

`scripts/ggsm_transcription` was run against the same archive.org source as
`_work/ssggsm-1985-08-21`, with the **same model** (Systran faster-whisper
`small`, snapshot `536b0662…`), the **same language**, and the **byte-identical
`initial_prompt`** — verified by SHA-256 (`59be219b…`) on both sides, diacritics
and en-dash intact.

| | Hand-made (2026-08-21) | Package (2026-08-27) |
|---|---:|---:|
| Segments | 856 | 810 |
| Words | 8,985 | 8,869 |
| First speech | 8.8 s | 8.8 s |
| Last speech | 5327.5 s | **5349.9 s** |
| Word overhangs | 9 (max 0.440 s) | 15 (max 0.400 s) |

**Token similarity: 85.8%** (difflib on case-folded word tokens).

Identical entry point. The package reaches **22 seconds further** into the
recording, capturing a tail the original run did not.

---

## 2. Why they differ

`_work/ssggsm-1985-08-21/asr-full.metadata.json` records:

```
model, model_name, language, requested_language, language_probability,
vad_filter, force_speech, initial_prompt, clip_timestamps, duration,
duration_after_vad, audio
```

It does **not** record:

| Parameter | Package value | faster-whisper default | Effect if they differed |
|---|---|---|---|
| `condition_on_previous_text` | `False` | **`True`** | **Large.** Governs whether each window is decoded with prior text as context; directly reshapes segmentation |
| `beam_size` | `5` | `5` | Small if equal, large if not |
| `word_timestamps` | `True` | `False` | Changes alignment output; words exist in both files, so it was on |
| `device` / `compute_type` | `cpu` / `int8` | — | Quantisation changes decoding at the margin |

`condition_on_previous_text` alone is a sufficient explanation for a ~5% segment
count difference and 85.8% rather than ~100% token agreement. **Which value the
original run used is unknowable from what it recorded.**

The faster-whisper version used in early August is also unrecorded; today's runs
pin `1.2.1`.

---

## 3. Why this matters

**A comparison against these transcripts cannot validate new code.** It was
attempted on 2026-08-27 as a reproduction check — same audio, same model, same
prompt, so any difference should have been attributable. It is not attributable,
because the baseline is underspecified. 85.8% is neither a pass nor a failure; it
is a measurement of how much two unpinned runs happen to agree.

**The transcripts themselves remain good.** Both were reviewed against word-level
timestamps and the published Taptajivanam reference, and both are in use. Nothing
here says the output is wrong — only that the *process* cannot be replayed.

**This is the problem `ggsm_transcription` exists to solve**, and today's run is
the first output in this project whose full recipe is recorded. `asr/metadata.json`
carries the complete configuration and runtime, and `_validate_fixed_configuration`
checks it on every read, so a future run either matches or fails loudly.

**But recording the recipe does not make the output reproducible.** See section 3a.

---

## 3a. The engine itself is non-deterministic

Measured 2026-08-27, after the comparison above raised the question. The same
21-minute clip, the same configuration, the same adapter class, two consecutive
runs in one process:

| | Segments | Words |
|---|---:|---:|
| Run 1 | 196 | 2,011 |
| Run 2 | 197 | 2,006 |

Two 5-minute runs *were* bit-identical, so this only emerges over long audio.
The full lecture showed the same pattern from the other direction: an
adapter-only run produced 810 segments and the CLI run 785, agreeing exactly
for the first 129 segments -- about 16 minutes -- before drifting by 0.02 s and
diverging in wording.

The cause is floating-point reduction order in CTranslate2's int8 CPU
inference, which is thread-scheduling dependent. `condition_on_previous_text`
is `False`, so context does not carry between windows -- but a small difference
in one window shifts the timestamps that position the next, and the divergence
compounds.

**Consequences, which matter more than the finding:**

- **A transcript cannot be verified by re-running it.** A re-run produces
  different bytes and therefore a different digest. The stored digest binds
  *this* output to *this* run; it is a seal, not a recomputable checksum.
- **"Reproducible" here means the configuration, not the transcript.** A future
  run is guaranteed to have used the same parameters, and guaranteed *not* to
  produce the same file.
- **Similarity between two runs of this pipeline has a floor below 100%**, even
  with everything pinned. The 85.8% against the August transcript is therefore
  an upper bound on how much of that gap is attributable to the unrecorded
  parameters in section 2 -- some of it is simply the engine.
- If bit-reproducibility is ever required it needs single-threaded inference or
  a deterministic backend, and neither has been tested here.

---

## 4. Consequences to respect

- **Do not treat `_work/*/asr-full.jsonl` as a regression baseline.** It is
  historical output, not a fixture. A future change that moves similarity from
  85.8% to 80% has not necessarily broken anything.
- **`_work/ssggsm-1985-08-08` is further out of reach.** It used
  `clip_timestamps: '330'` — skipping 330 seconds of intro — which the package
  cannot currently express at all. See the open items in
  `docs/superpowers/specs/2026-08-26-corpus-ledger-domain-design.md`.
- **The gap-filling passes are also unreproducible here.** They used `base.en`
  and a French-language pass; `_snapshot()` resolves only the Systran `small`
  repository, and naming another model now fails loudly rather than
  mislabelling.
- **If an exact replay of the August work is ever needed**, the only honest route
  is to sweep `condition_on_previous_text` and `beam_size` against the recorded
  output and see which combination reproduces it. That is an experiment, not a
  lookup, and nobody has asked for it.

---

## 5. What was verified along the way

Two defects surfaced only by running the flow against real audio. Neither was
reachable by any of the 130 tests then in the suite, because all of them use a
fake ASR adapter.

1. **`numpy.float64` rejected at the boundary.** faster-whisper returns float
   *subclasses* for segment and word bounds; the exact-`type()` checks guarding
   persisted evidence refused them. The flow could not transcribe anything at
   all. Fixed in `_segment_to_record`, the translation layer, so the strictness
   protecting persisted evidence is untouched.
2. **Word timestamps overhang their segments.** Word times come from a separate
   DTW alignment pass than segment boundaries and routinely fall a few hundred
   milliseconds outside. Strict containment **would have rejected both hand-made
   transcripts** — 9 violations in 8,985 words, 10 in 4,422. A tolerance of 1.0 s
   was measured from those two corpora (largest real overhang 0.44 s) rather than
   chosen, and confirmed against a third lecture-length run: 810/810 accepted,
   max overhang 0.400 s.

Both are instances of the same pattern found earlier the same day in
`DEFAULT_ASR_CONFIGURATION`: **a rule asserting something the tool never
promised, which only real data could disprove.**
